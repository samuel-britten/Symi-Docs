                                                                                            Undefined functions

                                                                                            An undefined function is a named unknown: a function symbol with no definition, such as the y of an ordinary differential equation. It is not an expression. It is a handle from which two things are built — a call y(x), and a structural derivative y′′(x)y''(x)y′′(x) — and those expressions are what the solvers, classifiers, and verifiers read.

                                                                                            Three different operations in this manual are spelled derivative or differentiate. They are not interchangeable:

                                                                                            Task Entry Page
                                                                                            Differentiate an expression now differentiate Calculus
                                                                                            Wrap an expression in an unevaluated derivative derivative Deferred forms
                                                                                            Build a derivative of a named unknown from argument orders derivative below This page

                                                                                            Constructing a named unknown#

                                                                                            undefined_function#

                                                                                            api::Session method

                                                                                            pub fn undefined_function(
    &self,
    name: impl Into<String>,
) -> UndefinedFunction

                                                                                            A callable proxy for a user-named function. The handle belongs to the context that made it, and every expression built from it belongs to that same context.

                                                                                            UndefinedFunction#

                                                                                            Type

                                                                                            pub struct UndefinedFunction

                                                                                            The handle itself. It carries no mathematical content beyond its name and its context; all of its meaning appears in the expressions it builds.

                                                                                            Calling the function#

                                                                                            call#

                                                                                            api::UndefinedFunction method

                                                                                            pub fn call<IteratorType>(
    &self,
    arguments: IteratorType,
) -> Result<Expression, ApiError>
where
    IteratorType: IntoIterator<Item = Expression>,

                                                                                            The function-call expression name(arguments...). Argument order is the function's own argument order and is preserved exactly; it is what derivative indexes its orders against. Python spells the same operation as ordinary call syntax, y(x).

                                                                                            Structural derivatives#

                                                                                            derivative#

                                                                                            api::UndefinedFunction method

                                                                                            pub fn derivative<OrderIterator, ArgumentIterator>(
    &self,
    orders: OrderIterator,
    arguments: ArgumentIterator,
) -> Result<Expression, ApiError>
where
    OrderIterator: IntoIterator<Item = usize>,
    ArgumentIterator: IntoIterator<Item = Expression>,

                                                                                            The structural derivative node of the named function — the shape the ODE and PDE classifiers recognise. There is one order per argument, matched positionally against arguments: y.derivative([1], [x]) is y′(x)y'(x)y′(x), y.derivative([2], [x]) is y′′(x)y''(x)y′′(x), and u.derivative([1, 2], [x, t]) is ∂x∂t2u(x,t)\partial_x \partial_t^2 u(x, t)∂x​∂t2​u(x,t). An order list whose length differs from the argument list is an error rather than a padded guess.

                                                                                            This is distinct from derivative on a context or an expression, which wraps an arbitrary expression in a deferred differentiation placeholder. Equations built from that placeholder are not recognised by the differential-equation classifiers, so an equation whose unknown is a named function must use the operation on this page.

                                                                                            Object identity and lifetime#

                                                                                            These members are owner-qualified here because name, session, and is_stale are member names many unrelated types share; each entry below documents the UndefinedFunction member and nothing else.

                                                                                            UndefinedFunction.name#

                                                                                            api::UndefinedFunction method

                                                                                            pub fn name(&self) -> &str

                                                                                            The name the handle was created with.

                                                                                            UndefinedFunction.session#

                                                                                            api::UndefinedFunction method

                                                                                            pub fn session(&self) -> Session

                                                                                            The context that owns the handle. Expressions built from a handle belong to that context, and mixing contexts is refused rather than silently rebased.

                                                                                            UndefinedFunction.generation#

                                                                                            api::UndefinedFunction method

                                                                                            pub fn generation(&self) -> u64

                                                                                            The context generation the handle was published in, which is what the staleness check below compares against.

                                                                                            UndefinedFunction.is_stale#

                                                                                            api::UndefinedFunction method

                                                                                            pub fn is_stale(&self) -> bool

                                                                                            Whether the owning context has moved past the generation this handle belongs to. The concept, and what to do about it, is explained once in Context safety.
