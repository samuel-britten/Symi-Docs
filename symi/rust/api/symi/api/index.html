§Safe native facade

symi::api is the recommended native Rust entry point. A session owns one symbol table and expression interner. Every expression, matrix, geometry handle, undefined_function, and cylindrical_algebraic_decomposition records that session and its reset generation. Mixing sessions or using a handle after session::reset returns api_error; it never reinterprets symbol identifiers.

The implementation-oriented modules re-exported from the crate root remain the advanced, context-affine engine layer. They expose interners, reference-counted expression nodes, and identifiers needed by Symi algorithms. Ordinary applications should import api::prelude.

§Construction and simplification

use symi::api::prelude::*;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let session = Session::new();
    let x = session.symbol("x");
    let two = session.integer(2);
    let one = session.integer(1);
    let square = session.power(&x, &two)?;
    let twice_x = session.multiply(&two, &x)?;
    let polynomial = session.add(&session.add(&square, &twice_x)?, &one)?;

    assert_eq!(polynomial.factor()?.to_string(), "(x + 1)^2");
    assert_eq!(session.rational(2, 4)?.to_string(), "1/2");
    Ok(())
}

Exact scalar construction is available through session::integer, session::integer_from_decimal, session::rational, session::rational_value, and session::rational_from_decimal. Primitive integer conversions use exact_integer_input; floating-point values are deliberately not expression-like. integer_from_decimal and rational_from_decimal are the canonical exact-text conversion points for host bindings and reject malformed literals with api_error.

The principal Lerch transcendent is constructed with lerch_phi; its canonical arguments are (argument, order, shift).

§Calculus and logical evaluation

The facade also exposes the exact analytic-domain operations taylor_series, laurent_series, singularities, and continuous_domain, as well as the guarded transform operations laplace_transform, inverse_laplace_transform, fourier_transform, and inverse_fourier_transform. An immutable assumption_scope provides the scope-aware evaluate_limit, taylor_series, laplace_transform, and continuous_domain variants.

use symi::api::prelude::*;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let session = Session::new();
    let x = session.symbol("x");
    let polynomial = session.parse("x^2 + 2*x + 1")?;
    let derivative = polynomial.derivative(&x, 1)?;
    assert!(derivative.to_string().starts_with("derivative("));
    assert_eq!(derivative.execute()?.to_string(), "2*x + 2");

    let deferred = session.limit(
        &session.parse("sin(x)/x")?,
        &x,
        &session.integer(0),
        LimitDirection::TwoSided,
    )?;
    assert_eq!(deferred.execute()?.to_string(), "1");

    let predicate = session.less_than(&session.rational(1, 3)?, &session.integer(1))?;
    assert_eq!(predicate.evaluate_truth()?, TruthValue::Yes);
    Ok(())
}

session::derivative, session::limit, session::execute, session::evaluate_limit, and session::evaluate_truth retain the same exact construct-versus-evaluate semantics as the language bindings.

session::integrate_definite_detailed returns a DefiniteIntegrationResult; the native method is integrate_definite_detailed. It takes a DefiniteIntegrationInterpretation (ordinary or cauchy_principal_value, resolved from host spellings by from_name) and an optional logical constraint that holds throughout the request. The result’s interpretation names the interpretation used and its verdict is a DefiniteIntegrationVerdict: an evaluated result carries its exact value; a divergent result carries a DefiniteIntegrationDivergenceDirection in divergence_direction when one signed infinity was established; and a declined result carries a DefiniteIntegrationDeclineReason in decline_reason. An ordinary improper integral exists only when every one-sided contribution converges, while a principal value pairs the two sides of each interior singularity and the two tails of a whole-line request. Its verdict is a DefiniteIntegrationVerdict: an evaluated result carries its exact value; a divergent result carries a DefiniteIntegrationDivergenceDirection when one signed infinity was established; and a declined result carries a DefiniteIntegrationDeclineReason. integrate_definite_numeric is the separate, explicitly approximate finite-interval operation. It returns NumericDefiniteIntegrationResult: value is present only after numerical convergence, estimated_absolute_error is the final difference between successive quadrature rules, and precision_bits and node_count describe the accepted computation. It never calls symbolic integration; unsupported bounds, singularities, or failed error control leave value absent.

The separate_partial_differential_equation session method derives independently verified one-variable ODEs and their exact reconstruction from a supported two-variable PDE.

session::simplify_trigonometric, session::expand_trigonometric, and session::combine_trigonometric perform their corresponding exact trigonometric rewrites. session::rewrite_trigonometric_basis takes the typed trigonometric_basis option, while session::rewrite_special_functions takes the typed special_function_basis option. These typed options centralize the stable spellings accepted by host adapters.

The special-function constructors are bessel_j, bessel_y, bessel_i, bessel_k, hankel_first_kind, hankel_second_kind, spherical_bessel_j, spherical_bessel_y, spherical_hankel_first_kind, spherical_hankel_second_kind, airy_ai, airy_bi, airy_ai_prime, and airy_bi_prime. They construct exact symbolic calls; use execute when a numeric evaluation is desired.

The symmetric elliptic constructors are carlson_rf, carlson_rc, carlson_rd, and carlson_rj. The Legendre parameter-form constructors are elliptic_k, elliptic_e, elliptic_pi, elliptic_f, elliptic_e_incomplete, and elliptic_pi_incomplete. They preserve exact calls; execute evaluates supported finite principal-branch cases and declines singular or principal-value-only calls.

The Jacobi constructors are jacobi_sn, jacobi_cn, jacobi_dn, jacobi_amplitude, jacobi_theta_1, jacobi_theta_2, jacobi_theta_3, and jacobi_theta_4.

The classical orthogonal polynomial constructors are jacobi_polynomial, gegenbauer_polynomial, chebyshev_polynomial_first_kind, chebyshev_polynomial_second_kind, legendre_polynomial, generalized_laguerre_polynomial, and hermite_polynomial, with ultraspherical_polynomial and laguerre_polynomial as convenience constructors that lower to gegenbauer_polynomial and generalized_laguerre_polynomial. Each takes a degree, then the family parameters, then the polynomial argument. A degree proved not to be a non-negative integer yields undefined; an unresolved degree stays a symbolic call.

expand_orthogonal_polynomial rewrites every such call whose degree is a proved concrete non-negative integer into its exact ordinary polynomial, leaving a call unchanged when its degree is unresolved or its expansion would exceed the construction budget. convert_polynomial_basis and orthogonal_polynomial_coefficient run the reverse direction, expressing a finite univariate polynomial in a requested classical basis. Both take an orthogonal_polynomial_basis, which names an orthogonal_polynomial_family and carries that family’s parameter expressions; from_name, name, and parameter_count describe a family, new builds a basis, and resolve binds one to the session that owns its parameters. A basis whose leading coefficients cannot be proved nonzero declines rather than dividing by a possibly vanishing normalization.

§Solving, sets, and structured outcomes

use symi::api::prelude::*;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let session = Session::new();
    let x = session.symbol("x");
    let equation = session.parse("x^2 - 1")?;
    let solution_set = session.solve_as_set(&equation, &x)?;
    assert!(solution_set.to_string().contains("-1"));

    let finite = session.finite_set([session.integer(1), session.integer(2)])?;
    assert!(finite.to_string().contains("1"));

    let outcome: ComputationOutcome<Expression> = ComputationOutcome::Declined;
    assert!(matches!(outcome, ComputationOutcome::Declined));
    Ok(())
}

Set-shaped solving preserves complete, empty, and declined mathematics in the returned symbolic set. Algorithms with extra certification data use computation_outcome, whose solved, empty, positive_dimensional, and declined variants do not collapse a rigorous decline into an empty answer.

§Matrices and geometry

use symi::api::prelude::*;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let session = Session::new();
    let one = session.integer(1);
    let two = session.integer(2);
    let matrix = session.matrix([
        [one.clone(), two.clone()],
        [two.clone(), one.clone()],
    ])?;
    assert_eq!(matrix.determinant()?.to_string(), "-3");

    let zero = session.integer(0);
    let origin = session.point_2d(&zero, &zero)?;
    let unit = session.point_2d(&one, &zero)?;
    assert_eq!(origin.distance_to(&unit)?.to_string(), "1");
    let circle = session.circle_2d(&origin, &one)?;
    assert_eq!(circle.area()?.to_string(), "pi");
    assert_eq!(unit.intersection(&circle)?.len(), 1);
    Ok(())
}

The facade provides matrix, point_2d, segment_2d, polygon_2d, triangle_2d, and circle_2d handles. Their operations validate provenance before inspecting entries or coordinates. Every geometry handle exposes a symmetric intersection method. Its heterogeneous result contains isolated point_2d, overlapping segment_2d, or overlapping circle_2d components; symbolically undecidable intersections return api_error::computation_declined instead of an incomplete or falsely empty list.

§Callable functions and CAD

session::undefined_function returns an undefined_function whose call and derivative methods validate every argument before interning a node. session::cylindrical_algebraic_decomposition returns a cylindrical_algebraic_decomposition with checked cell access and the cad_cell_kind enum.

§Error contract

api_error implements std::error::Error and preserves core parse, matrix, and geometry errors. api_error::category maps every error to the shared diagnostic_category; api_error::diagnostic produces the structured record used by Python and JavaScript. Fallible methods document failure through their Result type and do not panic on context mismatch, stale handles, malformed collection shapes, or declined computations.

§Invariants, panics, and feature gates

Every facade handle is tied to the session that created it and to the session generation that was current at creation. Methods validate that provenance before reading or combining handles. session::reset invalidates prior handles and returns a generation error if the generation counter is exhausted. Facade operations return api_error for caller-visible invalid input; they do not use panics to report context, collection, or mathematical-domain errors.

§Threads

Every public facade type — session, expression, matrix, the geometry and cylindrical-algebraic types, and the structured outcomes — is Send + Sync, and so are the core values they wrap. A session handle may be cloned and moved to another thread, and one session may be used from several threads at once: calls against it are safe and produce the same canonical results, diagnostics, and declines as the same calls made one after another.

Calls on one session do not yet overlap. The session serializes them while the remaining shared-state work lands, so using several threads on one session buys safety rather than throughput; independent sessions run fully in parallel today.

Two behaviours are worth knowing when threads share a session. session::reset retires every handle made before it, so a call racing a reset either completes against the generation it started in or returns stale_object — which of the two is a race the caller cannot predict. And a local assumption scope belongs to the call that opened it: it never becomes visible to another call, and it never changes the session’s durable assumptions.

The optional reference-validation Cargo feature enables an independent native numeric validator for development checks. It is not required by the facade, is not available on WebAssembly paths, and does not change symbolic results.

§Facade API coverage

The public types are api_error, session, expression, matrix, point_2d, segment_2d, polygon_2d, triangle_2d, circle_2d, undefined_function, cylindrical_algebraic_decomposition, computation_outcome, cad_cell_kind, geometry_2d, geometry_intersection_component, CompletedOperationReport, ExpressionGraphMeasurements, variable_like, LentContext, and exact_integer_input.

A Rust host that builds an application layer of its own reaches the engine through session::extend, which runs one host-supplied computation against the session’s own context and hands it a LentContext for the length of that call. The computation is an operation like any other: it charges the session’s work, emits the session’s records, observes the session’s cancellation, and reports stale_object when a reset raced it. The context is lent rather than given — LentContext borrows the session’s stores and cannot be carried out of the call — so an application layer computes on the session’s interner and generation instead of keeping ones of its own.

The state a public call accumulates — its cancellation, its work ledger, its diagnostic records, and its re-entrant memo — belongs to that one call. A session publishes only the immutable policy its calls capture at entry, through operation_defaults and set_operation_defaults, so two calls that overlap cannot cancel each other or spend each other’s allowance. A host that must reach a call while it runs names it in the session’s registry of running calls: active_operations lists them, cancel_operation stops one, and cancel_active_operations stops them all. What a completed call left behind is read with take_completed_operation_report or take_operation_records.

An embedder that entered through a synchronous boundary cannot use the registry, because the thread that would name the call is the one blocked inside it. What it has instead is the memory the library runs in, so api::host_cancellation publishes a fixed array of words there. The embedder reserves one word before it starts a unit of work with reserve_host_cancellation_slot, stores the ticket it was given into that word from wherever it is standing, and releases the reservation with release_host_cancellation_slot when the work returns. Every call started on the reserving thread while the reservation is installed observes the word, including the tasks those calls fork, and a store that arrives after the work it named has returned carries a ticket the next reservation does not answer to.

§Assumptions

The assumptions facade exposes assumption_proposition and assumption_scope. A session can build real, rational_assumption, integer_assumption, natural, positive_integer, positive, negative, nonzero, finite, complex, extended_real, infinite, irrational, zero, even, odd, prime, composite, algebraic, transcendental, defined, nonnegative, nonpositive, assumption_equal, assumption_not_equal, assumption_less, assumption_less_or_equal, assumption_member, and assumption_congruent propositions. assumption_greater and assumption_greater_or_equal build the corresponding reversed-order propositions. assumption_proposition_from_logical_expression converts supported logical nodes, and deserialize_assumption_proposition restores the versioned canonical representation. Propositions support and, or, and not; sessions construct formulas with logical_assumption_and, logical_assumption_or, and logical_assumption_not. Durable contexts support add_assumptions, clear_all_assumptions, ask, could_hold, assuming, all_assumptions, and assumption_report_of. Scopes support ask, could_hold, assuming, and assumptions without mutating the owning session, and carry the scope-aware operations refine, simplify, integrate, integrate_definite, evaluate_limit, taylor_series, laplace_transform, fourier_transform, singularities, and continuous_domain. Each one runs against the captured immutable formula through the same shared assumption session the durable entry points use, so a compound or relational fact reaches it exactly as a per-symbol declaration does, and an unproved side condition leaves the operation’s ordinary unevaluated or declined result rather than choosing a branch. Propositions expose stable_text and serialize for deterministic canonical spelling and persistence. Relational inspection uses relation_kind, left_operand, right_operand, membership_element, membership_set, and congruence_modulus. Refinement is available through refine on sessions, expressions, and immutable scopes.

defined and is_defined are pointwise: they state that an expression denotes one scalar value at the active point, and their negation states that it denotes none. Definedness implies neither finiteness nor continuity, the signed infinities are defined but not finite, and a point on a chosen principal branch cut such as log(-1) is defined even though the principal logarithm is discontinuous across that cut.
