                                                                Polynomial queries

                                                                These take ordinary expressions plus a variable name; the named variable becomes the main polynomial variable and every other free variable rides along symbolically in the coefficients. An expression that is not polynomial in the variable (a transcendental call of it, a non-integer power of it) makes the query decline — None for degree, an error for the others.

                                                                Gröbner bases and ideals#

                                                                These operate over the polynomial ring Q[variables]\mathbb{Q}[\text{variables}]Q[variables]. Generators are passed as an expression list; the ring variables are named by a string list; the monomial order is named by a string ("lexicographic" / "lex", "degree_lexicographic" / "deglex", or "degree_reverse_lexicographic" / "degrevlex", the computational default). Any generator that is not a polynomial over Q\mathbb{Q}Q in the named variables — a transcendental call, a non-integer power, an unnamed symbol, or an irrational coefficient — makes the operation decline cleanly (Python None, WASM null); it never returns a wrong or partial answer. Within Q[variables]\mathbb{Q}[\text{variables}]Q[variables] the results are exact and complete: a returned basis is the canonical reduced Gröbner basis, membership is a genuine decision, and elimination is exact by the Elimination Theorem.

                                                                Performance. The basis is computed by F4 (Faugère's batched Macaulay-matrix reduction), with a signature-based engine (F5 / GVW) available internally; the reference Buchberger algorithm is retained as the differential oracle these are checked against. The choice of engine is an internal acceleration only: the result is identical to the reference Buchberger basis for every input, and the monomial-order argument and the whole binding surface are unchanged. These entry points simply run faster — there is no new method to call.

                                                                groebner_basis#

                                                                Not exposed by the WASM / JavaScript bindings. Available as Context.groebner_basis in Python, UniffiSession.groebnerBasis in Kotlin, UniffiSession.groebnerBasis in Swift, api::algebra::Session::groebner_basis in Rust.

                                                                The canonical reduced Gröbner basis of the ideal <generators> under the named monomial order — monic, autoreduced, and sorted, so it is unique for the (ideal, order) pair. None when any generator is outside Q[variables]\mathbb{Q}[\text{variables}]Q[variables].

                                                                ideal_membership#

                                                                Not exposed by the WASM / JavaScript bindings. Available as Context.ideal_membership in Python, UniffiSession.idealMembership in Kotlin, UniffiSession.idealMembership in Swift, api::algebra::Session::ideal_membership in Rust.

                                                                Whether element lies in the ideal <generators>, decided by reducing it to its normal form modulo the Gröbner basis (zero exactly when it is a member). The verdict is independent of the order. None when the element or a generator is outside Q[variables]\mathbb{Q}[\text{variables}]Q[variables].

                                                                ideal_sum#

                                                                Not exposed by the WASM / JavaScript bindings. Available as Context.ideal_sum in Python, UniffiSession.idealSum in Kotlin, UniffiSession.idealSum in Swift, api::algebra::Session::ideal_sum in Rust.

                                                                A Gröbner basis of the ideal sum I + J, the ideal generated by the two generator lists together. None on a non-Q[variables]\mathbb{Q}[\text{variables}]Q[variables] generator.

                                                                ideal_product#

                                                                Not exposed by the WASM / JavaScript bindings. Available as Context.ideal_product in Python, UniffiSession.idealProduct in Kotlin, UniffiSession.idealProduct in Swift, api::algebra::Session::ideal_product in Rust.

                                                                A Gröbner basis of the ideal product IJI JIJ, generated by all pairwise products of the two generator lists. None on a non-Q[variables]\mathbb{Q}[\text{variables}]Q[variables] generator.

                                                                ideal_intersection#

                                                                Not exposed by the WASM / JavaScript bindings. Available as Context.ideal_intersection in Python, UniffiSession.idealIntersection in Kotlin, UniffiSession.idealIntersection in Swift, api::algebra::Session::ideal_intersection in Rust.

                                                                A generating set of the ideal intersection I∩JI \cap JI∩J, computed by the standard tag-variable elimination construction tI+(1−t)Jt I + (1-t) JtI+(1−t)J. None on a non-Q[variables]\mathbb{Q}[\text{variables}]Q[variables] generator.

                                                                elimination_ideal#

                                                                Not exposed by the WASM / JavaScript bindings. Available as Context.elimination_ideal in Python, UniffiSession.eliminationIdeal in Kotlin, UniffiSession.eliminationIdeal in Swift, api::algebra::Session::elimination_ideal in Rust.

                                                                A Gröbner basis of the elimination ideal ⟨generators⁡⟩∩Q[surviving variables]\langle\operatorname{generators}\rangle \cap \mathbb{Q}[\text{surviving variables}]⟨generators⟩∩Q[surviving variables], projecting away the variables named in eliminate via the Elimination Theorem (a block order ranks the eliminated variables high and the generators free of them are kept). Exact: it neither drops nor introduces components. None on a non-Q[variables]\mathbb{Q}[\text{variables}]Q[variables] generator. Example: eliminating t from {x−t2,y−t3}\{x - t^2, y - t^3\}{x−t2,y−t3} returns the twisted-cubic implicit equation y2−x3y^2 - x^3y2−x3.

                                                                Order change and implicitisation#

                                                                These consume a Gröbner basis rather than compute one from scratch. The order change runs the standard FGLM algorithm; implicitisation is parameter elimination with the rational-parametrisation saturation wired in.

                                                                change_monomial_order#

                                                                Not exposed by the WASM / JavaScript bindings. Available as Context.change_monomial_order in Python, UniffiSession.changeMonomialOrder in Kotlin, UniffiSession.changeMonomialOrder in Swift, api::algebra::Session::change_monomial_order in Rust.

                                                                Convert a Gröbner basis of a zero-dimensional ideal from source_order to target_order by FGLM (Faugère–Gianni–Lazard–Mora) — linear algebra in the finite-dimensional quotient ring Q[variables]/I\mathbb{Q}[\text{variables}]/IQ[variables]/I, far cheaper than computing the target basis directly (the msolve route to a lexicographic basis is a cheap degrevlex basis followed by this conversion). The result is the canonical reduced Gröbner basis under target_order, identical to a direct groebner_basis call. None when the ideal is positive-dimensional (the quotient ring is infinite-dimensional, so FGLM does not apply) or any generator is outside Q[variables]\mathbb{Q}[\text{variables}]Q[variables].

                                                                implicitize#

                                                                Default context

                                                                implicitize(
    coordinates: string[],
    parameters: string[],
    parametric_expressions: Expression[],
): Expression[] | undefined
                                                                Calling forms

                                                                Explicit context: Context.implicitize

                                                                implicitize(
    coordinates: string[],
    parameters: string[],
    parametric_expressions: Expression[],
): Expression[] | undefined

                                                                The implicit ideal of a parametric curve or surface xi=fi(parameters⁡)x_i = f_i(\operatorname{parameters})xi​=fi​(parameters) (the i-th coordinate paired with the i-th parametric expression), returned as a generator list over Q[coordinates]\mathbb{Q}[\text{coordinates}]Q[coordinates] — the elimination of the parameters (Cox–Little–O'Shea ch. 3). A polynomial parametrisation eliminates the parameters directly; a rational one fi=pi/qif_i = p_i/q_ifi​=pi​/qi​ clears denominators and saturates by the denominator product through a fresh tag variable, so the eliminant is the true implicit equation rather than a multiple carrying spurious components. None when a parametric expression is outside Q(parameters⁡)\mathbb{Q}(\operatorname{parameters})Q(parameters) or there are no parameters. Examples: {x=t2,y=t3}\{x = t^2, y = t^3\}{x=t2,y=t3} returns y2−x3y^2 - x^3y2−x3; {x=(1−t2)/(1+t2),y=2t/(1+t2)}\{x = (1 - t^2)/(1 + t^2), y = 2t/(1 + t^2)\}{x=(1−t2)/(1+t2),y=2t/(1+t2)} returns x2+y2−1x^2 + y^2 - 1x2+y2−1.
